Guide

An Obsidian vocabulary workflow for Arabic learners

Use one ordinary note as an Arabic ↔ English word bank, save to it while you read, and review it without leaving your vault. No plugin and no second database.

Updated November 3, 2026 6 min read Obsidian + any Markdown editor

Obsidian is good at keeping notes you already wrote. Vocabulary is different: it arrives in small pieces, while you read or watch something, and it is easy to lose. This workflow connects the two. Hassala saves each translated word or phrase to a Markdown note in your vault; Obsidian gives you search, links, and a place to review.

What you need

  • Obsidian installed, with a vault you already use (or a new one).
  • Hassala from GitHub Releases. The Chrome Web Store release is still being prepared.
  • Python 3 if you want saving to work.
  • No Obsidian plugin is required.

Step 1 — Create a word bank note

Inside your vault, create a note such as: 

Arabic/Word Bank.md

A folder per language or course keeps the vault readable. If you prefer one file for everything, put it at the vault root and name it Word Bank.md.

The note can be empty. Hassala adds a table on the first save. If you use the default file instead, Hassala creates it with these tags: 

---
tags:
  - english
  - vocabulary
  - hassala
---

That frontmatter is ordinary YAML, so you can edit the tags or add your own properties. A custom note keeps whatever frontmatter it already has.

Step 2 — Point Hassala at the note

  1. Open Hassala Settings.
  2. Under the word bank file, choose Choose file.
  3. Select the existing .md note inside your vault.
  4. Save the setting, then translate and save one word to test it.

The default path is ~/Documents/Hassala Words.md, which is only inside your vault if your vault happens to be ~/Documents. For most people, choosing the note explicitly is the safer option.

Custom files must already exist. Hassala creates only the default file automatically. It will not create a new note at an arbitrary path, and it will not write outside the file you choose.

Step 3 — Keep the table at the end

New rows are appended to the end of the file. That means the word table should be the last thing in the note. Add headings, sources, or comments above the table: 

# Arabic word bank

Source: Al Jazeera documentary, November 2026.

| # | English | Arabic |
| --- | --- | --- |
| 1 | get used to | يعتاد على |

If you write paragraphs below the table, the next saved row lands after those paragraphs — outside the table. Keep the table last and the format stays predictable.

What Hassala changes in the file

  • It adds the table if the note does not have one.
  • It normalizes the table header, separator, row numbers, and column order.
  • It may remove old generated title or section lines from earlier versions.
  • It does not rewrite prose outside the table.

Step 4 — Build a short review routine

A word bank only helps if you return to it. This routine takes about five minutes:

  1. Search the vault. Press Ctrl + Shift + F (Cmd on macOS) and search for a word you remember meeting. Searching by tag tag:#hassala finds the default word bank note.
  2. Open the note and read ten rows aloud. Reading aloud exposes words you recognize but cannot pronounce.
  3. Write one sentence with three of them. Put the sentence in your daily note, and link the word bank: [[Word Bank]]. The link makes the review note part of your graph instead of a dead end.
  4. Add context above the table when it matters. A source line or a short note about where you heard the word is enough.

Do not try to review the whole table every day. Ten rows is a habit; two hundred rows is a project you will postpone.

One file per course or series

If you are working through a course, a playlist, or a book, give it its own note: Arabic/Course A.md. Smaller tables are easier to scan, and the filename tells you where the words came from. You can still search across the whole vault.

Step 5 — Back up the vault

The word bank is a plain UTF-8 Markdown file. Use whatever you already trust:

  • Obsidian Sync or another sync service.
  • Git, if your vault is a repository.
  • A manual copy to another disk.

Hassala has no cloud and no account, so the backup is entirely your choice. That is also why nothing is locked in.

What this workflow does not do

  • No flashcards or scheduling. Hassala saves and deduplicates; it does not decide when you review.
  • No Dataview table. The rows are Markdown table cells, not frontmatter fields, so do not expect Dataview to query them as properties.
  • No automatic Anki export. CSV and Anki export are on the roadmap; for now, copy rows or convert the table with a script.
  • No page translation. Hassala translates words, selected text, and YouTube captions, not whole documents.

FAQ

Does Hassala have an Obsidian plugin?

No. Hassala writes a standard Markdown file. Obsidian reads that file like any other note, so no plugin or integration is required.

Can I use a note that is already in my vault?

Yes. Create or choose any existing .md file in the vault from Hassala Settings. The file stays where it is, and Hassala appends rows to it.

Will Hassala overwrite my notes?

Hassala normalizes the word table — header, separator, row numbering, and column order — and may remove old generated title or section lines. It does not rewrite prose outside the table.

Can I add my own notes below the table?

Avoid it. New rows are appended to the end of the file, so prose below the table would push later rows outside the table. Put notes above the table instead.

Does this give me spaced repetition?

Not built in. Hassala saves and deduplicates words. For scheduled review, use an Obsidian plugin, Anki, or a manual routine. CSV and Anki export are on the roadmap.

Does it work with Obsidian Sync?

Yes. The word bank is a local Markdown file, so Obsidian Sync, Git, or any file sync tool can carry it. Hassala does not sync anything itself.
